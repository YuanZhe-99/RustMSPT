# 放置检查点与有界几何

此设计适用于带 `placement:` 块的 `pack` 配置。旧版 `packing:`
保持不变。检查点保存的是计算状态；STL/JSON 可视化
导出和进度心跳则有不同的作用。

## 持久状态与安全点

默认启用的 `checkpoint` 会在配置的经过秒数/已接受颗粒数、协作式中断时以及正常任务
完成时写出 `checkpoint.json`。两个周期性触发条件都可以被禁用，而不会禁用
最终快照。在进行大型几何导出**之前**保存状态。若导出失败，
检查点仍允许重新生成导出。

带校验和的快照包含有序的已接受变换、精确的 f64 体积
累加器、拒绝/分组/失败尺寸计数、计划的尺寸种群、
ChaCha12 字位置、当前尺寸与已消耗的尝试次数、主/补抽游标，
以及补抽计量。团簇快照还额外保留已完成的模板
成员/搜索统计、全局代理/成员关系、混合阶段预留、
当前模板 ID 计划以及已消耗的团簇尝试次数。安全点出现在
一个完整评估过的投机批次或一个完整的被接受团簇之后。投机 RNG
回退在快照能观察到该状态之前就已提交。

已完成的模板可复用。在模板生成**过程中**发生的中断
会导出最佳的可行部分模板，但不会在检查点中将其标记为完成。恢复时
确定性地重新生成该当前模板，然后继续目录。FCC 的模板内部搜索不可恢复（接触生长可以，见下文）。
较早已完成的模板和已接受的全局团簇绝不会重新计算。

`serde_json` 使用 `float_roundtrip`，使恢复的 f64 值保持其位
模式。快照文件带有模式和对序列化状态的 SHA256。先写入
临时文件，flush/fsync，保留一份经过验证的上一代，然后原子地重命名，
并在 Unix 上对目录执行 fsync。缺失/损坏的所请求当前
文件会回退到其 `*.previous.json`。不兼容是一个错误，而不是静默使用
较旧状态的理由。不支持多个写入者并发写入同一输出目录；
请使用不同的目录。

周期性检查点 I/O 失败是硬错误，以免产生计算受到保护的
误导性声明。强制终止进程可能丢失自上次
已提交快照以来的工作，但不会因未完成的临时写入而使上一份已提交的
代失效。协作式停止仍会完成当前查询
批次和正常的几何导出；较长的查询/导出会延迟进程退出。

## 显式恢复与扩展

将 `checkpoint.resume_from` 设为保存的路径；相对路径相对于
YAML 所在位置解析。恢复从不自动进行。请移除旧的输出 `STOP` 标记。
使用新的输出目录以保留先前的可视化产物。

兼容性哈希涵盖实际解析后的物理配置、源字节、直方图、
孔隙以及精确的可执行文件。输出目的地/选项、线程数以及
内存/检查点控制可以更改。物理输入、每颗粒预算、
模板构造参数和采样策略必须一致。累计的
总尝试预算可以增加，但绝不能减少。全局预算停止会保留
未完成的抽取/候选，而不会错误地将其尺寸标记为耗尽。

已完成的检查点即使在目标已达成时仍然可用。显式的
`extend: true` 允许更高的全局 VF 目标，并根据剩余的真实
材料缺口进行规划，同时保留所有原始变换。先前的失败尺寸
计数仍会被报告。团簇扩展复用同一目录，并开始一个
新的主/回退周期。扩展未完成的快照会被拒绝：请先
完成它。更低的目标不属于延续。若不扩展，恢复一个
已完成的快照会重新生成输出，且不放置任何新内容。

旧的、检查点出现之前的 `particles.json` 文件缺少计划/RNG/尝试游标，
无法转换为精确可恢复的检查点。当前报告的经过时间
按每次调用计；尝试/材料/分组计数则是累计的。

## 几何驻留

生产环境的颗粒记录保存源标识、共享的规范源网格、
缩放/旋转/平移、包围球/AABB、分组、三角形范围和真实
体积。冷颗粒不持有世界系三角形或世界系 QBVH。一个不可变的源
壳可服务许多颗粒；源库内存与缓存
计量相互独立。恢复时会重新读取并验证该库。

精确的世界几何用与接受时相同的 f64 变换重建，
绝不从 float32 STL 重新加载。一个按字节计量的 LRU 缓存网格和 `TriMesh`。
并发请求会串行化构造，并共享缓存的不可变条目。
`Arc` 固定活动的查询几何；仍有活动持有者的保留条目不会
被选作逐出对象。若没有空闲条目能容纳，新的查询使用不保留的几何。
零缓存预算是有效的，且仍会执行精确检查。

字节计量包含对几何、拓扑和 QBVH 的保守的每顶点/每面
配额。它是**估计的保留缓存上限**，而非硬性的 RSS
上限。源网格、候选批次、活动固定项、模板搜索、空间
索引和输出缓冲区同样占用内存。`[GeometryCache]` 报告估计的
字节数、上限、条目数、命中数、重建数和逐出数。仅凭计数器
不能声称有性能/RSS 收益；请测量具有代表性的 release 运行。

## 保守的简化碰撞层

普通的粗筛阶段保留球和 AABB 测试。可选的
`memory.simplified_collision` 根据源包围范围构建一个由 12 个三角形构成的有向外包盒，
并以相同方式缩放/旋转/变换。一个小的向外余量
保护该外包。只有经证明的实体分离加上足够的间隙
才可绕过精确几何。代理重叠/包含是含糊的，会升级处理；
它从不直接拒绝一个可行的成对。没有外包/误差证明的普通三角形抽稀
无法安全地接受放置。

在代表性基准确立其收益之前，简化层默认关闭。它不改变源尺寸、VF 或导出的几何。
只要有必要，完整网格仍决定表面相交、实体嵌套和间隙。

孔隙包含独立于表面邻近性：一个被深深包围的颗粒
可能附近没有孔隙三角形。无条件的质心/实际顶点奇偶性
先于表面包围盒过滤。反向包围以及表面/间隙检查仍然保留。

## 输出与验证

颗粒 STL 按接受/面的顺序逐个流式输出重建的成员，
保留原始头部、零法向、float32 顶点和三角形范围。
不会累积出包含所有颗粒的合并网格。逐颗粒 STL 同样避免
构建碰撞层次结构。体素标签只固定分块候选几何，
并构建分块局部的查询，而不是保留所有世界网格/BVH。

回归覆盖包括：比较未中断与已恢复的颗粒/STL/CSV 及
统计信息；全部三种模式；已完成前缀的扩展；损坏代的
回退；修改输入后的拒绝；缓存禁用/代理启用的差分结果；
活动固定项安全；以及深孔拒绝。现有的放置/孔隙/标签/团簇
回归保护独立的碰撞与输出契约。


## 为新的填充任务导入现有装配

`placement.initial_particles` 接受 `record`、`report` 和 `existing_gap`。
这会从冻结的扁平记录启动一个新的单颗粒放置任务；它不是
对先前 RNG/引擎游标的精确恢复。它可以保留由
较旧可执行文件生成的种群，而不削弱检查点的可执行文件检查。

记录摘要必须与其原始报告匹配。检查模式、坐标系、源
顺序和哈希、冻结孔隙哈希、有限的变换、由源推出的直径、
体积、三角形范围、包围范围和计数。从 f64
源变换重建每个颗粒，并在声明的 `existing_gap` 下独立验证严格壁、孔隙包含和
真实邻居间隙。保留所有已接受的
变换及其顺序。新候选保持正常的颗粒间隙，而不是
较小的继承间隙。不会将任何代理作为实体材料导入。

新计划只覆盖缺失的真实材料体积；报告包含继承的
颗粒。初始化是事务性的：在完整的继承集合通过验证之前，
不会放置任何新颗粒。验证期间收到的停止会在
验证之后得到响应，并保存完整的继承种群；原始
文件保持不变。由该新任务创建的检查点支持精确恢复
和已完成扩展。初始记录/报告的字节计入兼容性。
请使用单独的输出文件。此模式要求检查点、单颗粒放置、
严格边界、feasible_uniform 或 free_space_guided 采样，以及禁止孔隙穿越。

模式 2 还额外保留引导单元和原始失败抽取。显式的
剩余计划转移可以读取模式 1/2，而精确恢复保持严格的
可执行文件标识。参见 [自由空间引导](free-space-guided-placement.md)。

接触生长模板还会为待处理的成员计划、已提交/最佳位姿以及插入/松弛游标保存检查点。恢复时会重放未完成的事务；模板内已完成的工作则被保留。FCC 仍会重建其被中断的当前模板。
