# 三角形或线段上的最近点

`closest` 子命令一次为大量查询点回答：一组三角形（一张曲面）或一组线段（一组线）中哪个图元最近、图元上的最近点以及距离。按输入曲面修复四面体网格的调用方，要对百万单元网格的每个节点或每个单元中心反复问这个问题（simHelper 的 `meshing/nearest.py`，被其闭合修复使用）；这里的一次调用替代了原先 VTK 的 `find_closest_cell` 或 numpy 穷举搜索。

## 规则

对每个查询点 `p`：

1. `p` 到每个图元的精确 `f64` 距离是到其最近点的距离：三角形按 Voronoi 区域求（Ericson，*Real-Time Collision Detection* 5.1.5），线段按截断投影求。面积为零的三角形取其三条边中最近的一条。
2. 距离最小者胜出。与最小距离相差在 `DISTANCE_TIE` = `1e-12`（相对）以内的图元视为并列，取其中图元编号最小者。
3. 结果是该图元、它上面离 `p` 最近的点和距离。图元集合为空时给出 `-1`、`NaN` 和 `NaN`。

并列容差带是规则 2 的关键。离两个三角形共享的棱（或几个三角形共享的顶点）最近的点，到它们的距离都相等；没有容差带时，各个距离的最后一位会决定选谁，而对按图元读取信息（例如所找三角形的法向）的调用方来说，这个选择是有影响的。VTK 对这种情况没有明确规则，所以在这些点上它给出的图元编号与这里不同，而距离和最近点在舍入误差内一致。

## 搜索

`PrimBvh` 是建立在每个图元精确轴对齐包围盒上的静态层次结构，构建方式与 `state-map` 的 `TetBvh` 相同：按盒心最长轴的中位数划分，按盒心再按编号排序，叶子最多四个图元。查询是两遍分支定界：第一遍求最小距离，先进入较近的子节点，跳过比当前最佳距离更远的盒子；第二遍只访问并列容差带内的盒子，保留编号最小者。盒子的距离不会超过到其中任何图元的距离，所以两遍都不会漏掉答案。

第一遍可以从一个**种子**开始：一个图元，用它的精确距离从一开始就限定搜索范围。种子只用于剪枝；这个界限是真实距离，不会小于最小距离，所以无论用什么种子或不用种子，答案都相同。

## 并行与 GPU

各查询点相互独立：CPU 路径在本次运行自己的线程池（`cpu_max`）中用 rayon 并行映射。结果与线程数无关。

启用 `gpu` 特性时，`GpuClosestSeedPipeline` 在 GPU 上以 `f32` 遍历同一层次结构，为每个点记录它找到的最近图元。坐标先在 `f64` 下减去根包围盒中心，再取整到 `f32`，所以远离原点的网格也能保持精度。这个图元在主机上作为该点的种子，主机随后执行上面的精确搜索。种子的距离在 `f64` 下重新计算，且只用于限定搜索范围，所以 `f32` 的舍入永远不会改变答案：CPU 和 GPU 给出完全相同的图元、最近点和距离。批大小随设备存储绑定上限调整。

`acceleration.mode`（或 `RUSTMSPT_ACCELERATION`）选择后端，规则与 `state-map` 相同：`cpu`；`gpu`（GPU 失败时报错，除非 `acceleration.cpu_fallback`）；`auto`（先试 GPU，失败则退回 CPU）。报告写明实际后端、适配器和回退原因。

## 输入与输出

运行示例见 [`examples/closest.md`](../examples/closest.md)，函数见 [`reference/pipeline-closest.md`](../reference/pipeline-closest.md)。数组以 `.npy` 文件传递（C 顺序、小端）：`vertices` `(n, 3)` f64，`triangles` `(m, 3)` 与 `segments` `(m, 2)` 二者恰取其一（整数顶点编号），以及 `queries` `(..., 3)` f64。输出为 `primitive.npy`（int64）、`closest.npy`（`(..., 3)` f64）和 `distance.npy`（f64），形状与查询的前导维相同，另有 `report.json`（`method_version` `closest-point-v1`、工具构建标识、规则、并列容差、图元类型、顶点/图元/查询数、后端、线程数、层次结构深度，以及读取、构建、种子、搜索、写出的耗时）。
