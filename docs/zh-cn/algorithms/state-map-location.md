# State-Map 点定位

`state-map` 子命令负责重网格化后状态传递中最耗时的一半：新网格每个单元的每个采样点，落在旧（变形后）网格的哪个单元里；对落在旧网格外面一点点的采样点，则在给定界限内找最近的旧单元。对定位到的值做平均、可接受性门限和映射报告仍由调用方（simHelper 的 `transfer/state_mapper.py`）完成；RustMSPT 只返回供体单元和距离。

## 规则

对每个查询点 `p` 和源四面体：

1. **包含。** 若有一个或多个四面体包含 `p`（每个重心坐标 `>= -1e-12`，且和 `<= 1 + 1e-12`），取形心离 `p` 最近（平方距离）的那个，并列时取编号小的。距离为 `0`。
2. **有界回退。** 否则取精确点到四面体距离最小的那个，前提是该距离 `<= fallback_distance`。与最小距离相差在 `DISTANCE_TIE` = `1e-12`（相对）以内的四面体视为并列，取其中编号最小者，并记录它自己的距离。旧网格外的点常常与几个四面体等距（最近的是它们共享的棱或顶点），没有这个容差带时，各自距离计算的最后一位会决定选谁，两个正确的实现就会给出不同结果。
3. **无。** 否则供体为 `-1`，距离为 `NaN`。超出界限的点不赋值；是否接受由调用方决定。

精确距离取六条棱线段与四个面上落在面内的垂足中的最小值，与 simHelper 的 `_distance_to_tetra` 算法相同。形心按 numpy 的求和顺序 `((v0+v1)+v2)+v3` 再除以 4；重心坐标来自以 `v1-v0`、`v2-v0`、`v3-v0` 为列的矩阵之逆。奇异四面体不包含任何点。

## 为什么用包围体层次结构（BVH）

最初的实现（simHelper）用半径 `fallback_distance + reach` 的球查询回答规则 2，其中 `reach` 是全网格**最大**的形心到顶点距离。在分级网格上（孔壁 0.5 µm 单元旁是 4 µm 背景单元），一个大单元决定了所有点的半径，孔附近 9.65 µm 的球里有 3–8 万个四面体。一次 1523 万个采样点的重网格化（其中 106,818 个在旧网格外）在这里花了 2 小时 22 分。

`TetBvh` 是建立在每个四面体自身轴对齐包围盒上的静态层次结构。规则 1 只进入包含该点的盒子；规则 2 是两遍分支定界：第一遍求最近距离，跳过比当前最佳距离（或界限）更远的盒子；第二遍只访问并列容差带内的盒子，取编号最小者；每个四面体都按自己的盒子被找到，而不是用全局半径。

每个盒子向外扩展其最大边长的 `1e-9`，以容纳重心坐标容差允许的所有点。层次结构按最长轴上盒心的中位数划分（按盒心再按编号排序），叶子最多四个四面体；构建是确定性的。

## 并行与 GPU

各点相互独立，CPU 路径在本次运行自己的线程池（`cpu_max`）中用 rayon 对查询数组做 `par_chunks_exact`。结果与线程数无关：每个点的供体由全序决定。

启用 `gpu` 特性时，`GpuTetCandidatePipeline` 在 GPU 上以 `f32` 遍历同一层次结构，为每个点记录所有包含该点的叶槽（最多 `gpu_slots` 个，同时给出总数）。盒子**向外**取整到 `f32`，点取最近值。取整是单调的，所以 `f64` 下在盒内的点在向外取整后的 `f32` 盒内也一定在：GPU 给出的槽是 CPU 要检查的槽的超集，主机随后用 `f64` 对它们执行规则 1。候选数超过槽数、或候选中没有包含它的点，完全在 CPU 上处理（先规则 1，再规则 2）。因此 GPU 只负责缩小搜索范围，从不做判定，CPU 与 GPU 的供体和距离完全相同。批大小随设备存储绑定上限调整。

`acceleration.mode`（或 `RUSTMSPT_ACCELERATION`）选择后端：`cpu`；`gpu`（GPU 失败时报错，除非 `acceleration.cpu_fallback`）；`auto`（先试 GPU，失败则退回 CPU）。报告写明实际后端、适配器和回退原因。

## 输入与输出

运行示例见 [`examples/state-map.md`](../examples/state-map.md)，函数见 [`reference/pipeline-state-map.md`](../reference/pipeline-state-map.md)。数组以 `.npy` 文件传递（C 顺序、小端）：`source_points` `(n, 3)` f64，`source_cells` `(m, 4)` 整数，`query_points` `(..., 3)` f64。输出为 `donors.npy`（int64）和 `distances.npy`（f64），形状为查询点的前导轴，以及 `report.json`（`method_version` 为 `state-map-locate-v2`、工具构建标识、规则、三个容差、包含/回退/未定位点数与 GPU 溢出数、后端、线程数、层次结构深度与节点数，以及读入、构建、定位、写出的耗时）。
