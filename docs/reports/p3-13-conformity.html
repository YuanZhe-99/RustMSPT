02 — what it wasSix measurements, each ruling out the obvious answer

The residual survived three months of repair work because every plausible description of it was wrong. These are numbered because they are a sequence: each one only became askable once the previous had been answered.

  1. It is not a T-junction. The split repair oscillates with period two. Two node chains run between the same two lattice nodes; split one and the other’s node lands on the face you just made. PLAN §6.58
  2. It is one arm disagreeing with itself. Tagging every node with the arm that interned it: 312 of a3’s 368 coincident pairs are trace-endpoint against trace-endpoint — not two arms computing one point, but one arm computing it twice. PLAN §6.59
  3. The separation is one float32 ULP. 2.98e-8 apart, and the two spellings are f32(0.3217) + 0.15625 against f32(0.8217) − 0.34375. Both input STLs are clean — 8 and 642 distinct vertices, nothing closer than 1e-6 — so it is not the file. PLAN §6.60
  4. The snap was never offered the partner. For every endpoint the rule declines to reuse, the nearest candidate it can see is 1e-1 to 1e-3 away and never closer. It was not refusing a node. Every bound tried until then was aimed at a gate that was not the obstacle. PLAN §6.62
  5. 296 of the 312 are on faces that share an edge. Recording the lattice face behind each endpoint: the pair’s x and y are bit-identical and both are cube face planes. The point is on the input’s feature edge, and each face cuts it with its own plane. PLAN §6.63
  6. The two faces are not coplanar — which decides everything. Publishing the partner and snapping to it takes a3’s traced cells 16,883 → 190 at any bound. A node two non-coplanar faces share must lie on their common line, or it is off one of the two planes and that face can no longer be triangulated at all. this step

03 — the fixA point two faces share can only live on the edge between them

Which is exactly what the on_edge path already does: it projects the point onto the edge and interns it per edge, so both owners get one node by construction. The residual was outside that path for one reason only — the bound guarding it.

// Or within the tolerance the contract calls coincident. The private `1e-9`
// relative bound is what left a3's residual outside this path: the pairs sit
// 6.7e-7 of the face's own edge from the rim, seven hundred times too far.
let close = off.dot(off) <= 1.0e-18 * len2
         || off.dot(off) <= coincident * coincident;
if close && (-1.0e-9..=1.0 + 1.0e-9).contains(&t) { /* project, intern per edge */ }
The bound is not a new number. 1e-6 × diagonal is [V2]’s own duplicate rule and the config’s coincidence: merge. It is a hundred times tighter than the eps that cost two points of on-surface area when this was last widened, and the projection moves a point by at most that — against features of 1e-4 and coarser. No setting chooses between a correct and an incorrect mesh (R3).

The fix is not free and the ledger should say so. Those are labelling, not conformity — the elements are in the right places and carry the wrong component names. That is the next target, and it is a smaller problem than the one just closed, because the mesh underneath it is now sound on every case.

Still open, and unchanged by this: a3 carries 3.75% of its material boundary off the input surface, against a1’s 0.21% and a6a’s 0.098%. That is the visible roughness along the cube/sphere intersection in the renders above, and it belongs to the fallback fan, not to conformity.
